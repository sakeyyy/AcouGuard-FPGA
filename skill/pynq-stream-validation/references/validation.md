# 验证矩阵与实机验收

## 已有证据分层

| 层次 | 可执行证据 | 能证明 | 不能证明 |
|---|---|---|---|
| 软件回归 | tests/test_stream_skill.py | 契约、错误处理、缓存 API 调用顺序、生成骨架及数值比较 | 实际 Overlay、DDR DMA、缓存硬件行为 |
| RTL 仿真 | 工程 sim/run_rtl.py | 原 packetizer 握手、数据、包边界、连续包、溢出复位 | I2S 外部时序、板级信号质量、长期吞吐 |
| 原实现报告 | reports 命令 | 特定源码实现的资源/已设约束时序及缺失约束 | 实测功耗、端到端延迟、优化收益 |
| 主作品上板视频 | report/onboard_test_record.md | 裸机整机功能示例 | 通用 PYNQ 包已在真实 PYNQ 系统运行 |

## 必须真正使用 PYNQ 才能验证的内容

1. 启动适配目标板 DDR/MIO/时钟的 Linux/PYNQ，记录系统、PYNQ 与驱动版本。不要将其他板卡镜像直接当本板镜像。
2. 用目标板硬件设计导出同次 BIT/HWH，填写契约；先 preflight，再 open_overlay，记录实际 IP 列表、register_map 和可选硬件签名。
3. 回环设计：生成确定性的整型测试向量，至少多次不同长度/边界测试，与独立 golden 比对；记录实际收发字节数、错误寄存器、输出哈希。不得传超过契约范围的长度。
4. 采集设计：提供 start/stop 回调，先 RX 后 arm；验证物理通道激励与时序。缓存验证应包含重复 DMA、CPU 修改 TX 和读 RX 的场景，不能只看一次全零。
5. 注入缺失 TLAST/断开流等安全故障，验证有界退出、停止与缓冲生命周期。硬件不可停止时先重载再释放保留缓冲。
6. 计时应重复试验、报告 warm-up/次数/中位与尾延迟，区分纯 DMA 和端到端；对比基线须同输入/器件/约束。跨板复用需第二块板分别完成这些步骤。

目前未提供上述 PYNQ 实机记录。可提交的真实成果是面向 PYNQ 的可执行工具、工作流、软件回归与工程 RTL 验证；不能把软件模拟改名为 PYNQ 上板成功。赛事额外加分是否认可此证据范围，应以评审要求为准。

## 复用边界

赛事四种示例的代码对应、五类跨题目场景和换板迁移步骤见 competition_mapping.md。新增 measurement.py 支持 register_map 字段只读采集与主机DMA调用性能报告，其软件测试见 tests/test_measurement.py；该报告的主机时间不等同PL周期或声学提醒延迟，真实结果仍按上文清单采集。

本工具不下载网络资源、不重建硬件、不包含通用 BIT 或操作系统镜像。一个 BIT 不能跨器件通用；复用的是接口契约、代码、测试与定位流程。receive_once 是单包 API，长期连续流须另验应用处理速度与缓冲策略。
